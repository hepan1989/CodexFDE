## 6. 修复过程中遇到的坑 (保留失败证据)

### 6.1 uv 缓存里 3.11 安装损坏
- 现象: `python3.11 -m venv .venv` 报 "Could not find platform dependent libraries <exec_prefix>" 和 `LookupError: no codec search functions registered"
- 根因: uv 缓存里两个旧 cpython-3.11 目录编译时硬编码 `/install` 占位前缀,
  `cpython-3.11.15-.../lib/python3.11/lib-dynload` 目录缺失,
  因此 Python 找不到 `_codecs` / `_io` 等 C 扩展。
- 解决: `UV_PYTHON_INSTALL_DIR=/Users/inhoufuku/.local/share/uv-python uv python install 3.11`,
  把新 3.11 装到当前用户可写的位置,
  再 `ln -sfn ~/.local/share/uv-python/.../python3.11 ~/.local/bin/python3.11` 改软链接。
- 遗留: 旧半残目录 owner 是 root, 无法本地 rm, 待手动 `sudo rm -rf`。

### 6.2 venv 切换 3.14 → 3.11
- `rm -rf .venv`
- `python3.11 -m venv .venv`
- `.venv/bin/python -m pip install -e .` → `Successfully installed flowerp-fde-camp-0.1.0`

### 6.3 git origin 误指老师仓库
- 现象: 默认 `git remote -v` 显示 origin 是 `congde/CodexFDE`,
  push 会污染老师仓库。
- 解决: GitHub 上 fork 一份到自己账户,
  `git remote set-url origin <fork URL>`, `git remote add upstream <teacher URL>`。
